# 性能理论重建：必要成本，不是当前成本

更新：2026-10-09。范围：五张 RX 6800 的普通单路生成，先不论 RERoT，不限制 CPU 为单线程。允许改变 TP 分片、调度、融合、缓存、表示和 MTP 策略，但不同数值/质量契约必须分别比较。

## 1. 撤回哪一条结论

**撤回“274 → 95–104 → 64.74–67.68 tok/s 已经逐步收紧到硬件必要上界”的推导。**

原始模型响应、微基准和性能配对保留。撤回的是它们被赋予的理论含义，不是删掉不合意的数据。尤其是：

- 273.86 是当前分片、复制、冷权重边界和逐阶段计费下的带宽商，不是所有合法实现的全局上界。
- 95–104 是现有着色器和原生算子代理的独立成本预算；不把模型总时间作为输入，并不能让它成为必要下界。
- 64.74–67.68 进一步使用了现有主通信协议的实测耗时及等待关系；它最多解释一种现有设计，不能证明更好的设计不存在。
- 66.64 预测与 67.15 实测接近、留出误差很小，只能支持预测准确性，不能支持最优性。

旧报告中的“不是硬件上限”但随后又用该数字暗示优化空间已很小，仍然有问题。不能靠免责声明保留错误推论。

## 2. 必须先改正不等号

设 A 是满足同一模型语义和质量要求、在同一硬件约束下允许采用的全部实现；T(a) 是同一负载、同一计时范围下的耗时。最优值为：

```text
T* = inf { T(a) : a ∈ A }
```

测到一个正确实现 a0 花15ms，只说明 `T* ≤ 15ms`。它不能推出 `T* ≥ 15ms`。
一个 shader 独立测得28.6μs，依然是某个具体实现的样本，不是该数学算子的最小可能耗时。微基准独立于模型请求，只解决了数据污染问题，没有解决这个量词问题。

真正的理论下界 L 必须满足：

```text
对所有 a ∈ A，都有 T(a) ≥ L。
```

一个可用实现提供同口径的可达耗时 U；只有在正确性也成立时，才有 `L ≤ T* ≤ U`。
所谓接近最优，是 `U/L` 接近1；不是预测值除以实测值接近1。实测 U 有噪声时还要保留置信范围，不能把一个样本当作确定常数。

固定的是推理任务，不是某几道基准题的答案。允许模型通用的预处理、无损重排和缓存，但要声明它们的存储及冷/暖计时边界；不能预存测试答案来代替推理。定义实现集合时不能悄悄禁止用户仍允许的MTP、换分片、跨阶段预取或算子融合，只为得到更接近当前速度的上界。

## 4. 三个反例，阻止再次把现状写成定律

### 4.1 层依赖不等于权重必须逐层读取

考虑两个有先后依赖的数学层、两条独立内存通道，读速率均为1字节/时间单位。第一层两卡要读90/10字节，第二层要读10/90字节；权重不可变、地址提前已知，每卡可容纳90字节的对应数据。

按原来的逐层计费：`max(90,10)+max(10,90)=180`。

一个合法的抽象读取排程是：第一卡0–90读取第一层、90–100读取第二层；第二卡0–10读取第一层，10–100预取第二层。第一层在90完成，第二层在100完成。第二层计算没有越过第一层的数学依赖，只是权重预取提前了。

因此，把逐stage读取时间相加作为所有实现的下界，需要额外证明无法预取/保留，不能仅引用层之间有依赖。

**这个反例不是本机已实现的提速。** 就当前清单而言，“逐stage取最大再相加”和“逐rank相加再取最大”恰好同为1,869,592,640B；反例检验的是证明规则，不能借它谎称当前公式已发现一笔预取收益。

### 4.2 多个必要成本不能自动相加

即使已经分别证明内存工作至少4ms、算术工作至少5ms，也只能直接推出总时间至少 `max(4,5)=5ms`。
要推出至少9ms，还必须证明这两段必要工作无法重叠。相反，使用 `max` 也必须说明共享的执行资源与依赖，不能把所有独立微基准任选一种加法凑到67。

### 4.3 小核加速没用，不证明大等待不可消除

若当前程序的汇合点是 `max(73.46,20.47)`，把第二项改为9.32不会改变结果。
这可以解释单工作组pack为何没有端到端收益。
但把第一项也改为10时，汇合点变为 `max(10,9.32)=10`。因此前一个负结果不证明73.46必要，更不能关闭重做通信/流水的路线。

这些反例已写为可运行检查；它们是数学/逻辑反例，不是伪造的GPU结果。

## 5. 每一条旧成本怎样重新定性

| 原来使用的量 | 目前成立的证据 | 不能推出的结论 |
|---|---|---|
| norm约28.6μs | 某个生产shader、指定内存布局的独立样本 | 所有等价norm都至少28.6μs |
| 主交接约73.46μs | 某个交接试验减去独立消费者的经验分解 | 真实协议固有常数，更不是硬件普遍延迟下界 |
| 96stage、1510dispatch | 当前 lowering 与图切分记录 | 模型必须发1510次kernel或96次CPU往返 |
| mailbox实际使用uncached类型 | 当前驱动选出的内存属性已经核实 | 所有正确设计都必须使用该内存布局 |
| 五卡复制HC/router | 当前plan的资源安排 | 模型必须五份读、五份算 |
| 390–403GB/s流式测试 | 某种访问方式已经达到的吞吐 | 所有访问方式都不可能更快 |
| 预测误差0.75%或2.23% | 当前成本模型有预测能力 | 当前程序离最优只差0.75%或2.23% |
| MTP1/deeper在某题更慢 | 该数值路径和负载的相对表现 | 无MTP的每步下界可以限制所有MTP策略 |

Vulkan规范规定可见性、一致性等语义，不规定CPU relay必须存在，更没有承诺一次交接必须花73μs。[R3]
FlashAttention保留精确attention的数学计算却改变I/O需求，也说明数学依赖并不等于当前中间张量物化方案必要。[R4] 这只是对错误证明方式的反例，不是声称已将该技术迁移到本模型。

## 6. 新理论怎样才有资格进入上界

### 6.1 资源项需要两份证据

若证明所有允许实现都至少消耗 W_min 单位资源，并且该资源速率不超过 C_max，才能写：

```text
T ≥ W_min / C_max
```

W_min不能是当前shader指令数或当前副本读取数；C_max不能拿某个实测吞吐值代替。浮点、整数、特殊函数也不能混用一个峰值单位。
硬件Roofline正是资源上限与工作强度的关系，不能把当前kernel时间改名为另一道硬件屋顶。[R1][R2]

### 6.2 一个确实可证明、但前提要公开的I/O引理

设一个区间必须消费U字节互相独立的原始数据，其中区间开始时至多C字节等价信息已在所选快存储边界内部；禁止更小表示、重构、代码常量或其他输入路径。那么至少 `max(0,U-C)` 字节必须跨过边界。

这是计数论证：边界内部最多已有C，剩下的必要信息必须进入。证明没有使用任何GPU计时。

但是，把它用于固定模型需要额外证明：哪些信息确实必须消费、哪些状态可跨token保留、寄存器/LDS/L0/L1/L2/Infinity Cache/预取缓冲算到哪里、代码常量与预处理是否绕过这个边界，以及允许多少行共同复用。
不能仅用“RX6800有128MB Infinity Cache”就声称已算出全部快存储容量。[R1]

作为**明确不具全局资格的反算**：假定4.614GB原始数据全部必须读取、初始可用数据为0、可自由均分到五条512GB/s通道，资源商只有1.802378ms，即554.82 tok/s。允许额外快存储保留后，这个I/O条件下界还会更低。

**554.82不是新的性能目标，也不是已证明的全局上界。** 它说明放开原来偷偷固定的分片/复制条件后，单靠这份字节账无法合法地把上界压向67。正确的重算有时会使界更松；不能为了满足“数值向下”而重新加入未证明的成本。

### 6.3 通信只能从必要信息流与物理资源推出

若固定一种分区，分区两侧各有私有输入，而对侧必须区分至少M种可能输出，那么最坏情况下至少需要传递 `log2(M)` 比特相应信息。把这种cut-set信息量除以跨cut的速率上限，可以得到条件资源项。

但分区、输出究竟需要完整Y还是更小的充分统计量、哪些数学状态可复制/预计算、是否必须全rank持有结果，都要允许优化。固定完整Y全归约协议后证明的下界，不能直接限制使用其他正确表示与分区的实现。
还要把字节吞吐与一次因果往返的最低时延分开；实测一次往返很慢，不是该最低时延的证明。

### 6.4 MTP必须保留在允许的实现集合里

用户没有禁止MTP。上界若要覆盖全部方案，就必须约束每个周期的工作量与可交付token数，再在允许策略中取最优；不能固定当前h=1或当前接受率。
同一周期总体的指标是 `总周期时间 / 总公开交付token数`，不是逐周期比值的任意平均。推测解码可以在固定target下改变计算排程和每周期产出，因此“自回归”不意味着每个公开token都必须完成一次独立、串行的完整target调用。[R5]

不同target量化/激活近似的语义契约要分开；MTP验证不能将改变后的target变回原target。bit-exact参考、既定误差契约、以及有质量门的近似模式不能共用未经说明的最优性结论。

## 7. 怎样继续优化而不把路线堵死

需要同时保存两本账：**可证明的必要成本L**与**实际可达成本U**。工程剖析是第三本解释账，帮助选实验，但不自动改变L。

理论侧从数学DAG与必要信息出发，对缓存、权重表示、分区、预取、融合和MTP建立放松问题；得到的是放松问题的最优值或可验证下界，而不是在旧lowering上求一条更漂亮的关键路径。计算与通信的共享资源、不同阶段可预取的条件都要明确。证明覆盖的实现集合缩小时，要标成条件界。

实现侧的主攻对象仍包括改变高代价host relay边界、减少重复HC/router工作、按实际消费者需求选择通信内容、跨阶段/多行复用以及MTP联合排程。这里不预先保证它们更快；用同模型/同数值契约的实际反例提升U。不能因为在原73μs等待下面压缩一个小核没用，就认定这些路线无效。

只有满足同一语义、负载和计时范围，且L的必要性成立、U的正确性与测量资格成立，才报告 `U/L−1`。理论缺口没证出来，就如实保留；不以临时改变基线、模型、输出长度或精度取得“Match”。

## 8. 这次实际完成的验证

新增 `scripts/tp5-necessity-audit.py` 与对应测试，重算源数据清单，并检查以下错误不会悄悄进入新账：将实测shader耗时当必要工作、将实测带宽当容量上限、将不同实现集合的下界混用、把可重叠资源直接相加、忽略MTP的公开token分母。

这些标签检查**不是自动定理证明器**；给条目写上“已证明”并不会证明前提。数学论证与约束审查仍不可省略。反例测试也不代表真实TP5实现已加速。

对已有 `run-20261009T0730/pack-b*` 的24份测量响应重新核对原始正文、token数、计时、退出、回退与实际binary/DSO/模型身份：对应正文一致，八次正常退出，一组身份。原基线重算 **67.5681447 tok/s**，单工作组pack候选 **67.4015693 tok/s**。它们只是既有实测，不作为L，也不是本轮新增GPU成绩。

本轮没有修改生产kernel、同步门、默认参数或硬件设置，没有GPU跑分。旧微基准、失败记录和已有未提交实现保留。理论入口和工具标签更新是为了撤销错误结论，不是掩盖之前的过程。
