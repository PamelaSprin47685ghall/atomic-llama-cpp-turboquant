# 神经编解码器路线图 (Wanxiangqi NLC)

本文档是对 `AGENTS.md` 中设计讨论的收敛结论 + 本仓库实际代码状态的对照 + 分阶段实现路径。
目标模型 /opt/llama/data/Ornith-1.5-MTP, 目标硬件 AMD RX 6800 (Vulkan, gfx1030, 16 GB, 512 GB/s, 128 MB Infinity Cache)。

调查日期 2026-08-28,基于 `master` @ `d29b2d5`。**所有行号均为该 commit 下的实测值。**

## 0. 两条硬规范

其余全部是这两条的推论。任何方案先过这两条。

1. **Never fully decompress weights.**
   压缩表示必须就是运行时表示。推论:AV1/HEVC 硬件解码器路线已死(解码带宽把省下的显存原价买回去);
   任何"解回 FP16 buffer 再 GEMM"的方案已死;所有工作必须落在 quant type + graph op 里面。

2. **数学变换是该付的代价。**
   判据是 `T_transform + T_compressed_GEMM + T_correction < T_baseline`,而不是 `T_transform = 0`。
   不允许为了 kernel 简单而丢掉变换,那会退化成"更聪明的 IQ3"。

### 目标函数

```
min  D_robust
     + lambda_M * resident_bytes          (常驻显存)
     + lambda_B * DRAM_bytes_per_token    (带宽)
     + lambda_C * dot_instr_per_token     (计算)
     + lambda_D * decode_instr            (codec overhead)

D_robust = mean(KL) + alpha * CVaR95(KL) + beta * std_domain(KL)
```

失真只用 KL,不掺 MSE、不掺 task score。rate 不是 bpw。
`3.0 bpw + 几十条 unpack 指令` 完全可能输给 `4.0 bpw + 一条 V_DOT8_I32_I4`。

### 校准纪律

`S_fit / S_select / S_OOS` 三分且绝不混用:

- `S_fit`:只允许估计 covariance / basis / permutation / entropy 统计 / sensitivity。
  现有 `wanxiangqi/calibration/` 的 270952 节点 trie 就是这个集合。
- `S_select`:只允许做 mode selection / lambda 选择 / partition 选择。
- `S_OOS`:冻结 bitstream 之前绝对不看,只用来报告 `D_robust`。
- 另做 domain-held-out:留出 code 测 code、留出 math 测 math。压缩决策在这些 split 下稳定,
  才说明找到的是模型本身的 redundancy,而不是语料的 redundancy。

任何 INTER reference 只能引用**已重建**状态(in-loop),不得用 teacher 原权重当 reference,
否则产生 encoder-decoder mismatch 和 teacher-forcing illusion。

### 目标形态

```
W ~= P_o D_o U_o * Q * U_i^T D_i P_i + R
```

`Q` 是共享低位核心(硬件友好的规则 INT4/低位),`U/D/P` 全部推到 activation 侧执行:

```
x -> (P_i D_i) -> U_i^T -> [Q: native low-bit dot] -> U_o -> (P_o D_o) -> y
```

MoE 特有的三个增益来源:tile 对齐的 structured neuron-atom SKIP(FLOPs 同时下降)、
跨 expert 的 prototype/palette、route coalescing(多个 routed expert 共享 prototype 时合并成一次 GEMM)。

## 2. 一处必须修正的数学:RHT 与 importance 不交换

这决定 KL 加权该加在**哪一层**。不先弄清这点,S2 会做错。

块内 RHT 是 `R = (1/sqrt(32)) * H * D_sigma`,`D_sigma = diag(+-1)` 是固定符号(`TQ3_0_SIGNS`)。
`R R^T = (1/32) H H^T = I`,正交。

设输入侧重要性为 `diag(a)`(imatrix 给的就是 `a_j = E[x_j^2]`),原域误差 `eps = R^T e`,
则旋转域中的度量矩阵是

```
M = R diag(a) R^T
  = (1/32) H D_sigma diag(a) D_sigma H^T
  = (1/32) H diag(a) H^T                      (符号约掉,因为 sigma_j^2 = 1)
```

两个后果:

```
diag(M)_k = (1/32) * sum_j a_j = a_bar        对所有 k 相同
M_kl      = (1/32) * sum_j a_j H_kj H_lj      即 a 自身的 Walsh 谱
```

**RHT 之后,per-column importance 塌缩成 per-block 标量 `a_bar_b`,外加任何对角量化器都无法利用的交叉项。**

现有的 `err += diff*diff` 不是"忘了加权",而是它已经等价于块内平坦加权。能加的只有块间。

### 三条可操作推论

1. importance-aware coding 的最细可用粒度是 **block**,不是 coefficient。
   S2 的产出必须是 block / row-group 级 Delta-Q,而不是块内重加权。

2. 想让块间差异变大,就要让每个 32-block 内的 `a_j` 尽量齐平,即沿**输入维**排序/置换。
   这就是"先建坐标系再分块"的落地:把无法利用的块内度量失配,转换成可以利用的块间码率分配。

3. 两种置换代价完全不同,必须分清:

   - **中间维置换 = 免费。** SwiGLU 的 `gate/up` 行 + `down` 列同步重排,纯权重重排,运行时零成本。
     服务对象是 row 敏感度 `s_i` 的分组 -> row-group Delta-Q + tile 对齐的 structured skip。
     这就是讨论里的 functional neuron atom `(W_gate[j,:], W_up[j,:], W_down[:,j])`。
   - **输入维置换 = 不免费。** 需要在 matmul 前对 activation 做一次 gather。
     它才是齐平 `a_j` 的那个置换。一层内所有 expert 可共享同一置换,摊到一次 op。

   **优先做免费的那个。**

### 待验证(S2 的前置实验,一个下午)

从现有 imatrix 直接量:32-block 内 `a_j` 的离散度(例如 `max/mean`、`std/mean` 的分布)。

- 若块内本来就平坦 -> 交叉项可忽略,现有 MSE 准则在块内已近最优,全部收益都在块间分配和 S1 的 side info。
- 若块内很尖(存在 outlier 列)-> 交叉项显著,输入维置换的价值大,值得付 activation gather 的代价。

这个数字直接决定 S2 做不做输入维置换。

## 3. 分阶段实现路径

每一阶段只动一个自由度,前一阶段是后一阶段的 baseline 和 primitive。**gate 不过就不进下一阶段。**

### S0 - 量尺与通路(不改任何算法)

1. **Vulkan 接线**(先决条件,RX 6800 上测不到曲线的话后面每一步都是盲的):
   - 在 `vulkan-shaders-gen.cpp` 注册 `dequant_tq4_1s` / `mul_mat_vec_tq4_1s`
     (参考同文件 `:855-862` 的 turbo set_rows / `turbo_wht` 注册写法)
   - 在 `ggml-vulkan.cpp` 补 TQ4_1S 的类型分派(pipeline 表 + `supports_op`)
   - `tq3_1s` 的 shader 需要新写,可等 S1 定稿后一起写(S1 会改块布局)
   - 验收:`test-backend-ops` 里 TQ4_1S 的 Vulkan vs CPU 对照通过
2. **RD 曲线脚本**:teacher logits 缓存一次(`--kl-divergence-base`),
   对每个候选量化跑 `--kl-divergence`,记录 `(bytes, mean, CVaR95, per-domain)`。
   CVaR95 在 `perplexity.cpp:1958` 的已排序 `kld_values` 上加几行即可。
3. **语料三分** `S_fit` / `S_select` / `S_OOS` + domain-held-out(留 code、留 math 各一轮)。
4. **基线点**:IQ3_XXS、IQ3_S、Q3_K_M、IQ4_XS、Q4_K_M、TQ3_1S、TQ4_1S。

**Gate:** 曲线可复现,且诚实读出 TQ 血脉当前在 IQ 曲线的哪一侧。
按 4.0 / 5.0 bpw 的 side-info 开销看,很可能现在是输的。这是预期,不是失败。

### S1 - 层级 scale(纯码率,零失真模型改动)

- `d0/d1` 两个裸 fp16 -> per-row fp16 + per-block 低位 log delta。
- 腾出的比特位留一个 codebook selector 字段(S4 用)。
- 只碰 `ggml-turbo-quant.c` + 各后端 unpack,数学完全不动。

**Gate:** 等 KL 下省 >= 0.4 bpw。**这一步过不了,后面都不用谈。**

### S2 - 把失真度量换成 KL(V1 的实质)

- **敏感度先不做 Fisher。** 用经验探针:一次只把一个 tensor / row-group 量化,
  在小 probe set 上直接测 `Delta_KL`。encoder 允许很贵(AV1 原则:encoder 可以极贵,decoder 必须极便宜),
  而且这测的是真目标,没有二次近似误差。per-tensor 几百次探针即可起步,per-row-group 上千次仍可离线跑完。
  解析 Fisher / Kronecker `H ~= A (x) S` 留作 S2 规模化的后路,**不是前置条件**。
- 中间维按 `s_i` 排序(免费),切成若干 row-group,对 group 做 water-filling 的 bit 分配:
  `R_i = 0.5 * [log2(gamma_i / nu)]_+`,`nu` 由目标总码率定。
- **落地不需要新 ggml 类型:按精度切分 FFN。**
  `gate/up` 按行切两段、`down` 按列切两段,两次 mul_mat 相加,FLOPs 不增(是划分不是复制)。
  MoE 下对应两次 `mul_mat_id`。代价是额外的 kernel launch,需实测。
- 块内目标函数保持旋转域 MSE(第 2 节已证明它就是块内平坦加权),
  但块/组权重换成实测 `Delta_KL` 导出的 `a_bar_b`。

**Gate:** 等 bytes 下 `D_robust^OOS` 优于 S1,且 domain-held-out 下结论不翻转。

### S3 - structured SKIP(时间空间同时省的第一个真实来源)

- 同一个 RD 判据,决策单元是 tile 对齐的 neuron atom:
  `Delta_KL_j < lambda_M * bytes_j + lambda_C * flops_j` 就**整个删掉**,不是给它 2 bit。
- 宽度候选取 GEMM tile 的倍数(512 / 448 / 384 / 320 / 256),
  避免"删了 17 个 neuron 但没变快"。RDO 的最小单位必须是 hardware execution tile。
- 必须是结构化的 neuron atom 删除,不是随机 weight sparsity。

**Gate:** bytes 和 FLOPs 同时下降,KL 不劣于 S2 的同等 bytes 点。

### S4 - palette / prototype(先离线证伪,再写代码)

- **纯离线研究**,不动代码:
  - 对 expert bank 聚类,量 K 个 prototype 在给定 KL 下能解释多少 (`E_i ~= C_k + Delta_i`)
  - 从 routing 统计量 co-occurrence,估 route coalescing 能把 8 个 active expert 合并成几个物理 GEMM:
    `sum_e g_e alpha_e P_c(x)` 聚合同 prototype 项
- 只有离线数字够强才动 MoE dispatch。这是潜在最大收益,也最容易做成无底洞。
- S1 腾出的 codebook selector 字段在这里变现。

**Gate:** 离线可解释率 + co-occurrence 统计支持"active expert 数实际下降"。

### S5 - 层间预测(最后)

- 只允许**不增加主 GEMM** 的残差形态:
  - Level-0: `W_l = D_o Q_g D_i`(一次 GEMM)
  - Level-1: 加 permutation `W_l = D_o P_o Q_g P_i D_i`(仍一次 GEMM)
  - Level-2: 寄存器内 codebook 修正 `q_l = q_g + delta_small`
  - Level-3: 仅异常 tile 追加计算
  - Level-4: low-rank `U V^T x`(最后才允许)
- `W_r x + Delta W_l x` 这种两次 matmul 的形态**默认拒绝**,除非 RDO 证明划算。
- 四相位结构 `10 x [D1, D2, D3, A]`:inter prediction 首先发生在**同 phase** 之间,
  距离定义为 `|l - r| / 4`。hierarchical depth B-frame(先解 anchor 再递归中点)可把误差传播深度
  从链式的 9 降到 log2(10)。
- 同样先离线验证:同相位层之间,Level-0/1 形态能达到的 KL 是多少。

**Gate:** 离线 KL 可接受,且 resident_bytes 下降幅度大于额外 op 的带宽代价。

## 5. 建议的第一步

从 S0 的 Vulkan 接线开始,理由:范围最小、可独立验证、不动任何算法,
而且它是"在目标硬件上能否测到 RD 曲线"的唯一前提。

```bash
# 1. 确认设备能力
build/bin/llama-server --version
# 检查 Vulkan 日志里的 integer dot product / subgroup 报告

# 2. 接线后的验收
build/bin/test-backend-ops -o MUL_MAT   # 关注 TQ4_1S 的 Vulkan vs CPU 对照

# 3. teacher logits 缓存一次(S_OOS 语料)
build/bin/llama-perplexity -m <teacher-f16.gguf> -f <oos.txt> \
    --kl-divergence-base oos-teacher.kld

# 4. 每个候选量化测一次
build/bin/llama-perplexity -m <candidate.gguf> -f <oos.txt> \
    --kl-divergence --kl-divergence-base oos-teacher.kld
```

第 3 步的产物是整条路线的量尺,应当尽早固定下来并且**此后不再改动 OOS 语料**。
