## 1. 静态审查：已排除项（位级/语义级验证正确）

- E1 `dequantize4_2aligned` BF16 位展开（`dequant_funcs.glsl:54-61`）：
  a=packed32[(a_offset+ib)/2] 覆盖元素 (2i,2i+1)；返回 vec4 = (低16左移16, 高16直用, b低16左移16, b高16直用)
  = 元素 (ib, ib+1, ib+2, ib+3) 的精确 F32 位展开。与 `dequantize4`（bf16_to_fp32 逐元素，:50-53）位等价。
- E2 HC_DOWN_SILU 的 0.25 折叠+SiLU 顺序（`mul_mat_vec_base.glsl:362-364`：
  `SiLU(temp*0.25)`）与 CPU 图一致（qwen4exp.cpp:383 `silu(scale(lo,1/hc))`），hc=4 有 dump 侧校验。
- E3 HC_UP_FOLD reduce（`mul_mat_vec_base.glsl:318-334`）：gate=sigmoid(temp)、product=fuse0·gate、
  Σ_n(n 遍历 NUM_ROWS 个 stream)、×0.25——与 mixed 公式一致；upfold 修复后的 weight_row 索引
  （`mul_mat_vec.comp:412-424` 与 iter() :333-336 两路径已对齐）。
- E4 down 段行映射两路径一致：`ib=(first_row+n)*p.ncols+col`（QUANT_K=1；iter() :331-340 与
  iter_aligned :410-427 同构）。B 读取：aligned 用 `data_b_v4[(j·stride_b+b_offset+col)/4]`（F32 vec4，
  host 侧已检查 stride_b%4==0、b_offset%4==0）；iter() 用 load_b 标量读 col..col+3（y_offset=1，
  QUANT_R=1）。元素配对正确。
- E5 `get_dm` BF16 返回 (0,0)（`dequant_funcs.glsl:546-550`）→ 无 scale/min 项，与 iter() 的 dm.y==0 分支一致。

## 2. 嫌疑清单（按嫌疑度排序，均 BF16 特有）

### S1（最高）host 侧 push constant 单位契约随 QUANT_K 变化
- 位置：`ggml_vk_segment_project`（ggml-vulkan.cpp，dispatch 侧 push 组装；本轮未读，见 §5 未决 1）×
  `mul_mat_vec_base.glsl:151-156` `a_offset = batch_idx_a * (p.batch_stride_a / QUANT_K)`。
- 机理：Q8_0 变体 QUANT_K=32（块索引语义），BF16 变体 QUANT_K=1（元素索引语义）。若 HC 专用 dispatch
  填 `p.ncols/stride_a/batch_stride_a` 时沿用 Q8_0 的块单位（或字节单位）约定，BF16 的 A 索引/offset
  系统性错位（×32 或 ×2），读到的权重行/列整体错。
- 兼容性：**完美**——读到同分布 BF16 权重的错误区域 → 值错但量级合理；错位确定性 → dump 跨轮逐字节一致；
  Q8_0 正常（同一 host 代码对 Q8_0 语义正确）→ 精确解释「Q8_0 对、BF16 错」。
- 核查点：dispatch 处 ncols/stride_a/batch_stride_a/stride_d 对 BF16 是否按**元素数**填写；
  `vk_mat_vec_push_constants` 组装处有无按 `ggml_type_size`/块大小换算。

### S2（高，与 S1 联动）dequantize4_2aligned 的 (a_offset+ib) 偶数对齐
- 位置：`dequant_funcs.glsl:55-56`（`(a_offset+ib)/2` 整除截断）× `mul_mat_vec.comp:430`。
- 机理：packed32 索引整除截断——若 `a_offset+ib` 为奇数，读错一对且 vec4 元素整体错位 1。
  col=4k 恒偶、ncols=hc_dim 恒偶 → ib 偶；唯 a_offset（=batch_idx_a·batch_stride_a/QUANT_K）可能引入
  奇数/错位——若 host 填的 batch_stride_a 非元素单位（回到 S1）。
- 兼容性：元素错位 1 → dot 结果错但量级同 ✓；确定性 ✓。

### S3（中）FORCE_ITER 时的 iter() OOB 分支与标量路径差异
- 位置：`mul_mat_vec.comp:364-381`（OOB_z 时 `dequantize1(ib+2/QUANT_R)`；OOB_y 时 `dequantize(ib)`）。
- 机理：QUANT_R=1 时索引正确；HC down K=4·width 4 整除 → is_aligned_nonquant 成立、OOB 分支不触发。
  风险仅在 ncols%4≠0 或 FORCE_ITER 诊断（push bit 0x200，`MAT_VEC_FUSION_FLAGS_FORCE_ITER`）下出现
  路径差异。**注意**：FORCE_ITER A/B 若结果不同，差异可能来自 B 的标量读取而非解码本身。
- 兼容性：低（正常形状不触发）；作为诊断工具的解读注意项。

### S4（中低）B 读取 16B 对齐 vs A 读取 4B 对齐的不对称
- 位置：`mul_mat_vec.comp:408`（B：vec4=16B，需元素 4 整除，host 已检查）vs `:430`
  （A：u32 packed32，需偶数即可）。
- 机理：B 的对齐条件在 host 侧 gate（is_aligned_nonquant），A 的对齐条件**没有**独立 gate——
  依赖 S2 的隐式偶数假设。若 S1/S2 破坏偶数性，A 读越界/错位而 B 正常。
- 兼容性：与 S1/S2 合并观察。

### S5（低，记录在案）多 token 行（n_rows>1）时 A/B batch 解耦
- 位置：`mul_mat_vec_base.glsl:137-148`（batch_idx_a 经 ne12/broadcast 折叠，权重无 batch——设计意图）。
- 机理：B 的 batch（token）与 A 的 batch 解耦正确；仅当 host 误把 token 维填进 A 的 batch 时出错。
- 兼容性：低；dump 单 token 时不可见。

## 3. CPU 参照对拍方案（交 DevOps 执行）

### 3.1 输入规格（全部来自既有 dump，无需 GGUF 重读）

| 文件（site1 r0） | dtype | 语义 | 长度（从字节数反推） |
|---|---|---|---|
| `tp5-hc-dump-site1-r0-normalized-<layer>.bin` | F32 | xn（gamma·rms，[4·width, n_rows]，行=token） | bytes/4 = 4·width·n_rows |
| `tp5-hc-dump-site1-r0-weightsA-down.bin` | BF16(u16 LE) | dispatch 实际绑定的 W_down（含 rank 切片视图） | bytes/2 = hc_lr_slice·4·width |
| `tp5-hc-dump-site1-r0-weightsA-up.bin` | BF16(u16 LE) | dispatch 实际绑定的 W_up | bytes/2 = up_rows·hc_lr_slice |
| `tp5-hc-dump-site1-r0-lo.bin` | F32 | down 段输出 SiLU(0.25·W_down@xn) | hc_lr_slice |
| `tp5-hc-dump-site1-r0-mixed.bin` | F32 | up 段输出 0.25·Σ_b(xn_b⊙gate_b) | width 或 up_rows（见 3.3） |

形状自洽规则（执行时反推，不猜）：
`width = len(normalized)/4/n_rows`（n_rows 从 server.log 的该 site 行数确认；单 token decode =1）；
`hc_lr_slice = len(lo)`；`up_rows = len(weightsA-up)/hc_lr_slice`；`len(mixed)` 与 up_rows/width 的
关系决定 up 段切片解释（3.3）。

### 3.2 参照计算（numpy，float32 复现 kernel 精度；float64 版作仲裁）

```python
import numpy as np
def f32(p):  return np.fromfile(p, dtype=np.float32)
def bf16(p):
    u = np.fromfile(p, dtype=np.uint16)
    return (u.astype(np.uint32) << 16).view(np.float32)   # 位展开，与 kernel E1 一致

norm   = f32('...site1-r0-normalized-<layer>.bin')[:4*width]        # token 0 切片
W_down = bf16('...site1-r0-weightsA-down.bin').reshape(hc_lr_slice, 4*width)  # 行=输出 k，行优先
W_up   = bf16('...site1-r0-weightsA-up.bin').reshape(up_rows, hc_lr_slice)   # 行=输出坐标

# down 段：lo = SiLU(0.25 · W_down @ xn)     [qwen4exp.cpp:382-383]
d     = W_down.astype(np.float32) @ norm.astype(np.float32)
lo_ref = (0.25*d) / (1.0 + np.exp(-(0.25*d)))

# up 段：gate = sigmoid(W_up @ lo)；mixed = 0.25·Σ_b(xn_b ⊙ gate_b)   [qwen4exp.cpp:384-400]
g     = W_up.astype(np.float32) @ lo_ref
gate  = 1.0/(1.0 + np.exp(-g))
mixed_ref = 0.25 * ((norm * gate).reshape(4, width).sum(axis=0))    # 当 up_rows==4·width
```

### 3.3 up 段切片的两种解释（按 len(mixed) 自动选择）

- 若 `up_rows == 4·width` 且 `len(mixed)==width`：gate 覆盖全 4·width，按上式 reshape(4,width) 折叠。
- 若 `up_rows < 4·width`（up 段按 rank 切了输出坐标或 stream）：mixed_ref 取
  `0.25·Σ_b(norm[该 rank 的 stream/坐标切片] ⊙ gate 对应切片)`；切片规则用
  `up_rows` 对 `4·width` 的整除关系推断（如 up_rows==width → 每 stream 同一坐标块，
  gate=reshape(up_rows, hc_lr_slice) 后按 (b,j) 映射）。两种解释都算，与 dump mixed 对拍择一。

### 3.4 对拍判读规则（期望误差形态）

1. **lo 对拍（第一优先，判 down 端）**：`rel = max|lo_ref−lo_dump| / max(|lo_dump|)`。
   BF16 权重 + F32 累加（K≈4·width，数千项）下 CPU/GPU 累加顺序差的期望相对误差量级 1e-4..1e-3。
   - `rel < 3e-3` → **down kernel 正确**；嫌疑移向 up/mixed 段或 dump 之后的环节。
   - `rel > 5e-2` 或出现下述结构性模式 → **down kernel 定位成功**。
2. **结构性模式判读**（lo 错时细分）：
   - **错位**：`np.correlate(lo_dump, lo_ref)` 找峰值偏移 Δ；Δ≠0 → 权重行错位（S1/S2 实锤）。
   - **比例**：lo_dump ≈ c·lo_ref（c≈0.25/4/32/2）→ 折叠系数/单位换算错（S1）。
   - **元素交换**：lo_dump ≈ 用相邻元素交换后的 W_down 算出的值 → dequant 位展开元素序错（S2）；
     可用 `lo_ref_swapped`（W_down 每行 reshape(-1,2) 交换列）复算验证。
   - **无结构随机**（量级同）→ 权重读错区域（S1 的 ×32 错位）；此时把 dump 的 weightsA-down 与
     GGUF 原始 `blk.<il>.hc_attn_down` 的 BF16 字节逐段比对，确认 dispatch 绑定的权重视图本身对不对
     （若 weightsA 本身就错位，问题在 capture/绑定，不在 shader）。
3. **mixed 对拍（第二优先）**：同阈值。lo 对而 mixed 错 → up 段（gate/fold/切片）；
   lo 与 mixed 同错 → down 端为根因（mixed 的输入 lo 已错）。
4. **A/B 诊断补充**（DevOps 可选）：设 push constant fusion bit 0x200
   （`MAT_VEC_FUSION_FLAGS_FORCE_ITER`，`mul_mat_vec.comp:32`）强制走 iter() 标量路径：
   乱码消失 → 错在 aligned 专属路径（dequantize4_2aligned / B 的 vec4 读取，S2/S4）；
   仍乱 → 共享路径（行映射/reduce/host 契约，S1）。
5. **仲裁**：float64 复算一遍 lo_ref64；若 lo_dump 与 lo_ref(f32) 的差远大于
   |lo_ref64−lo_ref(f32)|，差异来自实现而非精度。

### 3.5 输出物（DevOps 回报）

- 每个对拍：rel 误差、最大绝对差位置 k、错位相关峰 Δ、模式分类结论（正确/S1/S2/其他+证据）。
- lo 与 mixed 的前 16 元素值对照表（含 dump 锚点三值 0.232353/0.132684/0.203644 的复核）。
- 反推出的形状表（width/hc_lr_slice/up_rows/n_rows）与 server.log 的层名。
