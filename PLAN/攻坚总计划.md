## 1. 先定总方向

现阶段不要再把“获得完整真机分布”设为所有优化的开工许可。改为两条同步进行的主线：**测量线修复并重采可信基线；实现线按已证实的结构浪费交付可关闭候选。** 数据决定候选的默认启用和后续投入，不阻止 CPU oracle、契约测试、Shader 编译、独立算子实现。

近期主攻顺序建议：**测量纠偏／版本对齐 → Compact Span 的 GPU 展开桥 → Live Q-prep → 多行投影／公共 KV 多读者 → Target 容量闭环与传输对照 → 驻留状态池／图定义族。** 有明确生产占比后可调整相邻项。按层 LateBind 选择优先于 RMS 预测；精确线性 Chunk 预计算优先于跨非线性预测；Q8 跳块和 Q10 联合投机保留独立研究预算，不做其余任务的前置条件。

这不是 GPU 吞吐收益承诺。尚未取得当前版本的模型端到端数据，排序依据是当前源码中的浪费、可验证性、依赖关系与改动范围。

### 1.1 统一“进展”的口径

每项任务记录四条独立状态，不再用一个“已闭环”概括一切：

| 维度 | 状态示例 | 意义 |
|---|---|---|
| 实现 | 未实现／候选实现／集成完成 | 是否确有生产可调用的代码 |
| 正确性 | CPU oracle／实际 GPU dispatch／模型与状态对拍 | 覆盖到哪一层，不能相互冒充 |
| 性能 | 未测／微基准胜／端到端胜／负结论／噪声内 | 是否取得目标硬件同口径证据 |
| 发布 | 实验关闭／定义期条件选用／默认启用 | 默认用户是否实际受到影响 |

代码可在关闭状态下完成交付；未测速不得说提速；没有设备执行的测试不得写“GPU 数值通过”；没有收益的完整实验可关闭为负结论，不必无限重做。

## 2. 本次只读审计：必须修正的事实

### 2.1 版本与环境

实际目录是 `/home/kunweiz/atomic-llama-cpp-turboquant`，不是附件列出的 Desktop 路径。审计时分支 `master`、工作树干净、HEAD 为 `f51efe820`。附件主基线 `5d7a28e39` 之后有文档提交；更重要的是，附件尾部所附 `dc505e4c3` **不在目标仓库本地对象库中**。

`src/llama-kv-cache.cpp:5000–5215` 现有代码是第十八轮共享常驻扫描；`base` 与 `runs` 仍在 per-view 循环内构造。不能据附件的第十九轮描述，直接认定 shared run buckets／base zero-copy 已进入这台机器。先找回补丁并比较；取不到补丁不应无限等同步，应针对当前实现独立完成同一任务。

只读资源快照：5 个 AMD 设备的 `gpu_busy_percent` 均为 0，单设备显存使用约 17.2 MB；主机内存约 121 GiB、可用约 117 GiB，磁盘可用约 260 GiB。旧交接里“开发机只有 iGPU、磁盘 98%–100%”不能套用到当前目标机。**这些快照不证明驱动、AER、内核日志和退出链路安全，也不构成启动授权。**

### 2.2 不应重写已经实现的容量区

`src/llama-context.cpp:2409–2618` 确认：`evaluate_target_capacity_admission` 仍拒绝 GDN/recurrent、多序列、PLE、QSA 等不支持组合。`docs/TP5-TARGET-CAPACITY-PLAN.md` 第 7 节又明确记载多个区域已经完成实现或局部验证。

因此 M3 的下一步不是“从 0 重写 48 层”，更不是“删掉 gdn_unsupported”。应以当前可执行路径核对区域覆盖，修剩余漏项，补完整模型和跨卡证据，最后对经过验证的配置精确放行。

### 2.3 LateBind 的真实准入限制

`ggml/src/ggml-vulkan/ggml-vulkan-collective.cpp:2631–2649` 的 `tp5_late_consumer_ref` 当前要求启用 LateBind、RELAY、F32 wire、5 ranks，并限制容量行不超过 `VK_TP5_DIRECT_COLUMN_TILE`。

所以必须区分：**Vulkan 计算设备数、TP rank 数、逻辑 Reader/Pen 数、每序列验证 active 行数**。RERoT 的 b=6 投影优化，不代表 LateBind 现在支持容量 6；M3 第一阶段单序列 TARGET，也不等于多 Pen 容量化完成。用默认 TIMELINE 或错误 wire 配置测速，不能声称测到了当前 LateBind。

### 2.4 吞吐验收器并未完全闭合

源码核验：`scripts/rerot-throughput-gate.py`、`tools/server/server-context.cpp:10795,10839,10847`。

| 已核实问题 | 为什么需要修 | 必交付修复 |
|---|---|---|
| 正确性检查使用 `last_deltas` | 前面某轮发生 abort／计账错误，最后一轮正常可能掩盖它 | 每一轮单独判定，再 all(sample_ok) 汇总 |
| `pens_allocated`、`batch_pens` 是 gauge，却做 before/after 差 | 请求末端状态不代表请求过程峰值／实际并行参与 | 用 request-scoped peak、事件或累计活跃行计数；gauge 不冒充 counter |
| 无 parallel token/time 时退回 aggregate | 没有真实多 Lane 证据也可能获得“并行吞吐” | 报 N/A 或 not-exercised；语义成功与并行证据分开 |
| route gate 默认关闭；METRICS 未纳入它随后读取的 route 键 | 不能确认新 kernel 被执行；启用参数本身不会生成证据 | 注册实际事件／计数，并以本次请求差分证明命中 |
| `prompt_ms` 填成 `ttft_ms` | prompt 计算时间不等于客户端收到首 token 的时间 | 该字段改名；单独使用流式采样测 TTFT |
| A/B 实际是同一服务 RERoT OFF/ON | 不是旧 SHA／新 SHA，且两边 token 与时间口径不同 | 分开做“实现版本对照”和“调度策略对照” |
| 统计是中位数分别计算后比较 | 不是配对差／配对比，不能替代漂移与噪声评估 | 保留每个配对，输出配对效应及区间 |
| missing metric 返回 0 | 数据缺失与真实零值混淆 | 输出 missing；必需字段缺失时报告 evidence-incomplete |
| 可加载历史 baseline response | 没有模型／版本／编译／状态一致性验证 | 默认不用于正式配对；匹配 manifest 后另列历史参考 |
| HTTP timeout 的帮助文字关联 watchdog | HTTP 超时不取消 GPU 工作，不是设备恢复机制 | 明确区分请求 deadline、GPU wait 与安全排空 |

另有计数口径风险需验证：`q_prep_rows` 写在 `src/llama-graph.cpp:4551–4559` 的图构建函数内。不能不检查重放次数，就把它与执行期 `live_groups` 相除，进而当作真实 GPU 时间占比。构图次数、派发次数、实际处理行和 GPU duration 应分开。

### 2.5 测试登记不等于测试证据

`ctest --test-dir build-tp5 -N -R 'rerot|xkv|flashprefill|tp5|mtp|predefined|vulkan'` 枚举到 59 项相关测试，但 `build-tp5/bin/test-rerot-shared-block` 不存在。本次没有执行这些测试。以后必须记录 requested／built／executed／passed／failed／skipped／missing，不得把 SKIP、只建 pipeline、旧二进制或枚举成功算作 GPU 正确性通过。

### 2.6 附件中的两个推论需要纠偏

附件 Q5 给的粗略阈值 `d_k*d_v / (2*(d_k+d_v))`，在 `d_k=d_v=128` 时算得 **32**，不是 53。它仍只是成本近似，不是 GPU 上的固定转稠密阈值。应测得交叉点再固化。

附件“25 MB 压到几十字节”仅在 Span 极少且无 spill 的特定形状成立。新口径必须是 **16×n_spans + spill_bytes + offsets/groups 等必要元数据**；覆盖不足、碎片化或多 query 时可能是 KB 乃至更大，不能预先写死几十字节。

## 3. 安全不再是总闸，而是实验资源的局部调度

### 3.1 一次性定义运行包络，不对每个任务重复请示

当前用户请求是制定计划，不是启动授权。下一执行轮应由负责人一次性确定一份 `run-envelope`。包络是未来工作的授权记录，不是自生成的许可证。

| 类别 | 包络内可持续执行 | 不允许扩大成全局阻塞 |
|---|---|---|
| E0：不提交 GPU 工作 | 读取、局部改动、CPU-only 编译／测试、独立 oracle、Shader 离线编译、mock 故障注入、日志回放 | 某 GPU 路径未获批，不影响这些工作 |
| E1：单设备有限算子 | 经批准的设备、固定大小、有限 dispatch 的对拍和微基准 | 失败只冻结涉及的设备／Kernel 路线，不冻结 CPU 与其他开发 |
| E2：五卡有限协议测试 | 经批准的 rank 集、同步模式、固定自旋预算、输入变异／连续 epoch | 必须先核对本次实际运行配置；不把历史短测当无限压力许可 |
| E3：模型请求 | 经批准的模型、显存／上下文／token／请求数上限、隔离监听与唯一执行器 | 在包络内逐级晋级；新增破坏性操作才另作决定 |

包络至少记录：机器与设备 UUID／BDF；模型路径及 hash；构建配置；允许的同步模式；固定 spin 预算；最大 n_ctx、active、capacity、readers、W/P；每任务显存上限；有限请求预算；排空机制；故障停机线；负责人。模型变化、同步协议变化、排空生命周期变化、超出批准规模需要重评对应部分；普通 tile 候选不应每次重走全项目审批。

必须写清楚：TIMELINE 不因“默认”就被宣布绝对安全；RELAY 不因“实验”就永远不能推进。两者都根据本机事故史、实际配置与本次证据纳入受控包络。不得把 CPU-gated STAR 换名为 RELAY。

### 3.2 自动检查只做有限、明确的事

实验入口检查：GPU 设备占用与进程归属、显存预算、日志权限、从上一次实验 cursor 起的新增 GPUVM／hang／AER 错误、上一个任务是否已排空。检查失败输出具体 reason、证据位置和下一可做任务。

健康指标缺失记为未知，不伪造“正常”。未知可阻止相应 GPU 实验，但不阻止 E0 开发；应同时建一个可执行的“补观测”任务。旧故障只做一次完整处置／基线建档，后续看新事件，不能每个 patch 重审全部历史日志。

### 3.3 真正保留的停机线

禁止无界 GPU 自旋、超时后不断扩大 spin bound、关闭 watchdog、伪造完成信号、对不可能满足的 peer signal 调用无界等待、对未知完成状态提前析构资源。不能把 `kill -9`、进程 abort、`timeout` 外壳、GPU reset 或主机 reboot 当通用自动恢复。

发生 DeviceLost、GPUVM fault、hang、未满足依赖或无法证明完成时，停止该设备集的新提交。等待只能针对实际成功提交的 timeline 值；部分 rank 提交失败时，不等待并未提交的值。原生有界 wait 返回 timeout 仍是未完成，不是取消，也不是“现在可以释放”。无法安全排空时保留隔离状态及资源，由操作者处理设备恢复；其他 Agent 自动接着做不需要这些设备的工作。

这是工程隔离，不承诺软件能消除全部驱动／内核故障。Khronos 的原生 wait 有 timeout 返回语义，但这不等于取消设备工作【K1】。

### 3.4 提交前的局部回退，而非错误后的掩盖

形状不支持、容量不足、内存预算不够、某 expert／sampler 不适用，可以在提交前显式选择语义相同的旧路径并记 route。提交后发生部分失败，不能偷偷重发另一条路径，更不能把错误结果标成成功。

显存预算按每 rank 最坏占用计算，预留权重／KV／scratch／graph buffers／rollback。`VK_EXT_memory_budget` 是变化的估计，不是 OOM 保证；预留安全余量、处理 allocation failure 和保留 host fallback 都必须存在【K2】。建议初始 headroom 可用“每卡至少 2 GiB 或批准预算的 20% 中较大者”，但这是可调实验策略，不是硬件保证；若模型本身无法满足，就缩小经允许的上下文／实验状态规模，不擅自改变模型。

## 4. Agent 工作规则：禁止空转，允许未启用代码落地

### 4.1 角色与并行度

建议逻辑上设置四个实现角色和一个独占 GPU 执行器；这不要求五个 Agent 同时在线。一个 Agent 可按同一队列串行扮演多个角色。

| 角色 | 负责 | 文件冲突纪律 |
|---|---|---|
| A：布局／输入 | R13、R02、H16/H17 | `llama-graph.cpp`、`llama-kv-cache.cpp` 同时只安排一个整合者 |
| B：GPU 算子 | R07、R09、Q3、Q6、Q7 | 新 shader 可并行，`ggml-vulkan.cpp` 集中合并 |
| C：状态／容量 | TM3、R10、R12、Q5、Q9/Q10 状态部分 | recurrent、frame、server 状态机统一接口 |
| D：通信／收益 | T1C、T2、T3A、Tnorm、R14/TM5 | collective 生命周期单一所有者 |
| V：验证执行器 | 测试队列、模型基线、性能裁决 | 同一设备集只有一个负载所有者；其余只提交实验包 |

每个开发角色最多一个代码任务在做、一个候选待 GPU；GPU 执行器只跑一个任务。共用基线一次重测、共用结果一次归档，禁止五个 Agent 各自起五卡压测或各自重造台账。

### 4.2 单任务固定交付协议

每张卡必须输出：**一个待验证假设、明确文件入口、最小实现／最小复现、独立 oracle、路线命中证据、性能与显存变化、关闭开关、下一动作。** 所有新增脚本应有 dry-run 和自身单元测试。

不能以“需要真机数据”作为 Shader／CPU 契约尚未实现的理由；也不能以“只剩验证”为由长期不写可运行的 harness。没有胜出证据可以暂不启用，但提交关闭候选和实验包依然算实质进度。

### 4.3 遇到阻塞的状态转移

```
任务受阻
  ├─ 缺设备窗口：提交编译产物/输入fixture/预期输出/实验命令 → 转下一个E0任务
  ├─ 缺模型：使用真实格式的合成形状与独立oracle → 模型项另列待验证
  ├─ 缺trace：增加最小trace入口，同时做结构已知的候选，不先搭大监控系统
  ├─ 配置不支持：记录not-exercised，缩小到已定义形状或保留旧路由
  ├─ 数值失败：最小化反例，修局部候选；不下调全局容差
  ├─ 性能为负：记录原因与适用形状，回退默认，进入下一候选
  └─ 设备故障：冻结GPU提交，保留证据，转CPU开发/日志分析
```

任何“BLOCKED”必须同时附 `blocked_scope`、证据、解除条件、负责人和立即可做的替代任务；不得只有一句“安全门未批”。一次 patch 不超过一个新数学假设／同步协议假设；主分支默认路径保持可恢复。

## 6. RERoT 七项：逐卡实施

### R02｜Live Q-prep：先取消填充计算，再融合 WHT

**来源：附件第一部分缺口一。入口：** `src/llama-graph.cpp::build_rerot_q_groups`，Vulkan 算子注册／dispatch／shader 生成；`rerot_q_prep.comp` 为建议新增文件。

**实现次序：** ① 定义 raw Q、query-index、effective_pos、n_live、capacity、head_dim/heads、RoPE mode/frequency 的 CPU 契约；② 先实现 live gather+RoPE，不同时重写 WHT；③ 物理输出 stride 保持 capacity，工作量以 active 派发，尾块线程只能做必要掩码；④ 核验所有消费者不读 inactive 输出，调试时用毒值检测；⑤ 再评估 WHT 融合，不能把 RoPE 与 WHT 顺序交换。

**必测：** live=0 的可表达空任务／拒绝语义、1、cap−1、cap、cap+1 拒绝；head dim 非整 tile；非连续 Q；重复 query index；MROPE/IMROPE/普通 RoPE；大 effective position；不同 freq_factors。复用 `test-rerot-ddvr`、`test-rerot-attn`；新增实际 Vulkan Q-prep 对拍和 replay 1→4→1→2。

**交付证据：** 同一数值模式下输出对旧链的 atol/rtol；实际处理行、dispatch 和 GPU 时间；kernel 真命中。2%/15% 只能是可调投资阈值，不能把填充行比直接当总耗时比，也不能因此不写候选。未知 mode 提交前走旧链并记录原因。

### R07｜多行／PQ2_0 投影：先复用权重 Tile，不先开 LUT 战线

**来源：附件第一部分缺口二。入口：** `ggml-vulkan.cpp` 的投影 supports_op／recipe、现有投影 shader 与 quant block helpers。

**实现次序：** ① 用当前真实权重格式构造 b=1,2,3,4,6 形状；② 输出可执行的拒绝原因矩阵，不只汇总 unsupported_shape；③ 从 b=2/4 的共享 weight-tile 路径开始，扩展3/6尾块；④ PQ2_0 每块128元素，scale、编码、打包偏移沿用当前定义；⑤ 定义期选择 GEMV、小矩阵或旧路径，热循环不在线 autotune。

**必测：** K/M 边界、128块边界、尾部、非零 tensor offset、非均匀 TP head map、四个实际量化码值。独立解码+dot oracle；不得用同一个打包 helper 自测自证全部正确。加 b=1 回归与实际 recipe hit。

**收益账：** 单行延迟、整批延迟、每个有效行成本、权重读取／解码次数、VGPR/LDS。b=6 是本算子支持范围，不自动扩大 LateBind 的容量4限制。Q7 LUT 等本路径有矩阵级基线后再比较。

### R09｜长短 Reader 分桶与非均匀 Head Map

**来源：附件第一部分缺口三。入口：** `ggml-vulkan.cpp` RERoT attention dispatch，`flash_attn_rerot.comp` 与 split reduce。

**实现次序：** ① 从 `query_offsets` 得到逐 Reader 的真实长度；② 首版只设短／长两个长度桶，短行 split=1；③ 用任务描述表／间接参数表达每个 query 的 split_count、partial_offset、head子集，保持预定义图容量布局；④ 在 head-map 相同且可见语义相容的小组内共享 K/V 加载；⑤ 确认 reduce 遍历实际 partial 数，不读上一轮尾部。

**必测：** 长度0、1、tile±1，以及100与32768混合；不均匀 GQA；所有 head 恰好覆盖一次；空 split；连续小→大→小；不同归并序对同一 FP32 oracle。不能因 head 共享 physical KV 就共享 softmax 状态。

**关闭条件：** 新增分桶／dispatch／归约成本超过节省时，该形状保留旧路由。别让大量细碎桶取代原先的大块并行；桶数量首版有明确上限。

### R10｜逻辑 State 驻留池：先 D2D parking，再索引化

**来源：附件第一部分缺口四。入口：** server 的 pen handoff、`capture_hand_seed`／restore；recurrent backend 状态接口。

**实现次序：** ① 列出必须保存的 recurrent/conv/索引状态、KV可见性与位置、Sampler/RNG和pending decision；② 明确 GPU 大块与 CPU 小元数据的所有权，不承诺把所有状态都变成GPU字节；③ 实现 `logical_lane → native_state_slot → physical_pen` 映射；④ 同设备先做有界 D2D 复制的 parking；⑤ kernel 支持槽索引后才考虑零复制重映射；⑥ slot 直到最后读者完成才可复用，generation 防 ABA；⑦ 超预算提交前走原 host 存档。

**必测：** W=P、P+1、2P；同槽反复换入换出；接受与拒绝后的状态；分配失败；slot被占用；取消／pending decision；reset/restore；单卡与TP各rank一致性。对照“从未换笔”轨迹，不只比较最终一条文本。

**收益账：** pen_yields、序列化字节、D2H/H2D/D2D、每次换笔延迟、峰值显存、整DAG完成时间。native copy 不重新量化状态；跨卡拷贝与同卡 D2D 不混称。

### R12｜阶段预定义图：结构事件付费，运行期只喂数据

**来源：附件第一部分缺口五。入口：** `llama-context`、`llama-graph`、predefined frame、阶段调度。

**实现次序：** ① 先用真实 `graph_def_count` 原因桶列出 probe、fixed-entry、BODY、多Lane、synthesis 的结构差异；② 只为已闭合输入／状态契约的常见阶段定义 family，给出实例数和内存上限；③ 每个实例定义时确定拓扑、物理stride、route和buffer寿命；④ 运行期只更新active／位置／数据，结构事件在安全边界重新定义。

**重要边界：** 这不是每轮 fingerprint/cache validation。保留 active<=capacity、epoch／slot及地址边界等廉价安全约束，不做全图重审。不要为所有 token 数全组合预建图，也不能用“永久图”掩盖模型／容量／拓扑变更。

**必测：** 阶段往返、同阶段活跃行变化、输入地址寿命、回滚、无输出phase；统计稳态 graph_def/CB-record/buffer-growth 的增量。目标为所覆盖形状的这三项增量归零。M3 TARGET 仍遵守单 verify_tokens 容量，不建 verify_2/3/4 图族；prefill 范围不顺手扩大。

### R13｜Compact Span ABI：两步落地，第一步就产生可测收益

**来源：附件第一部分缺口六。入口：** `llama-rerot.h`、`llama-graph.cpp::fill_spans`、`ggml_flash_attn_ext_rerot`、CPU/Vulkan 后端。

**R13-A（优先）：** 保留 attention 的 dense entries 消费，新增版本化 compact 描述输入；CPU 只上传 spans+必要spill；GPU 用小展开 kernel 生成当前 epoch 的 entries，供布局相同的层复用。展开结果按 layout身份／epoch管理，不能跨不同层布局盲目复用。这个桥接阶段不同时重写复杂 attention。

**R13-B（后续）：** 在同一 ABI 上增加原生 span 消费的 attention 变体，再去掉完整 entries 物化。CPU fallback／外部旧调用保留真实兼容路径，不让两份描述成为各自独立的权威。

**契约与必测：** `{key_start,count,group_index,entry_index}` 各字段范围及乘加溢出；span单调且不重叠；gap／spill必须有权威来源；重复 storage、多query、部分 ownership、SWA／ring wrap、zero count、乱序拒绝。expanded stream 逐slot等于既有 entries oracle。展开→attention 的计算读写依赖必须显式满足【K3】。

**收益账：** Host生成、staging、上传、GPU展开、attention和总请求分别计时。记录上传字节与span覆盖率，而不是固定“几十字节”。不能在 R13-A 前删除旧 entries 发射；覆盖不足时允许显式 dense fallback。

### R14｜RERoT 端到端净收益：每波都跑，不最后才跑

**来源：附件第一部分缺口七。入口：** `rerot-throughput-gate.py`、semantic smoke、DAG reference、多Lane请求脚本。

**实现次序：** ① 完成第2.4节全部脚本修复及反例单测；② 分开“旧实现 vs 新实现”的同工作负载对照与“串行DAG vs 并行DAG”对照；③ 固定模型、数值模式、可见性规则、输出预算和采样配置；④ 配对记录全部请求与route；⑤ 分开 Target-only、MTP、全特性组合。

**必测拓扑：** Flat、链加独立节点、Diamond；STRONG/LAG1；W=P 与 W>P；固定入口／prefix rebuild／synthesis；取消和重复请求。完成相同DAG才比较任务墙钟，内部生成更多 token 不能自动当用户更快。

**交付：** 每一轮语义合格、任务完成时间、最终有用token、内部forward token、首token、p50/p95与完整原始数据。全特性设置但route未命中，结论只能是 not-exercised。与 TM5 共用验证框架，但不混用模型基线。

## 7. TP5 / MTP / LateBind 六项：逐卡实施

### T1C｜Host Push／Local+Publisher／BAR Pull 对照

**来源：附件第二部分缺口一。入口：** `ggml-vulkan-collective.cpp`、LateBind sidecar生产者、publisher与CPU reduce路径。

**实现次序：** ① 把三种传输选项落实为定义期不可变选项；② 固定相同Q8Packed算术、F16/F32 sidecar格式、rank/active、输入、数值模式；③ 记录每rank producer完成、ready可见、CPU读取/归约、下行发布、下一消费者真正开跑；④ 按当前LateBind准入使用RELAY/F32/5rank，或明确这是另一个实验模式。

**必测：** payload→ready 的发布顺序、generation、环槽复用、延迟rank、缺失ready、CPU读取格式、错误路径。host-imported不自动代表L3命中，BAR映射不自动代表廉价、cache coherent也不免除执行依赖；实际内存属性与协议要记录。

**裁决：** 比端到端关键路径而不是publisher dispatch数。首版按机型和层组固化胜出方案，不做每token动态三选一。传输候选的生命周期和下行同步不应同时重写；否则无法归因。

### T2｜按层 LateBind 与 Inverse-RMS 分成两个独立子任务

**来源：附件第二部分缺口二。入口：** collective HC plan、层定义、LateBind／resume shaders。

**T2-A（优先）：** 先用离线或独立校准 workload 统计每HC点的关键路径、量化误差与可隐藏窗口，生成固定 LayerPlan；候选为普通Q8 HC、LateBind精确模式、已声明的aggressive模式。未收集样本的层保留原已知行为。生成计划的校准集与正式验收集分开，避免挑层过拟合。

**T2-B（研究）：** 320维sidecar预测 rho 先只shadow预测误差，不向后传播。只有证明后续局部计算能通过精确校准还原时，才进入精确候选；一旦预测通过非线性、离散量化或采样且无法精确修正，就按近似路径独立评价质量、接受率与净收益。

**必测：** 完整模型逐层误差、长序列积累、不同active、MTP接受率；不能用“F32 scale更精确”推出模型质量和接受率必然提高。先交LayerPlan，不让预测研究阻塞它。

### T3A｜粗粒度 Chunk 跨层重叠：先算线性可提前部分

**来源：附件第二部分缺口三。入口：** collective的分块生产／归约、HC消费者、下一层投影。

**实现次序：** ① 以2560维和真实Q8块对齐验证4×640这一候选，非该模型形状重新派生；② 对一个chunk，先归约所有rank得到完整全局chunk；③ 该chunk到齐后，提前累积下一层线性 `W_chunk * y_chunk` 和完整chunk平方和；④ 所有chunk平方和到齐后求精确rho；⑤ 仅在代数允许的边界应用rho和偏置，再进入不可交换的非线性。

**数学红线：** `||Σ_r y_r||²` 含rank间交叉项，不能用 `Σ_r ||y_r||²` 替代。若提前投影的是rank本地部分，也必须证明线性求和、精度模式及scale处理完整。不能把局部RMS称为完整RMS。

**必测：** scalar oracle、rank延迟、chunk乱序准备、缺块、最后非整块、rho极端、带gamma/bias的真实投影；重用buffer不能与未完成消费者冲突。通过已支持的命令依赖表达，不新增不受控GPU等待。

**收益账：** 完整请求关键路径减小量，另列额外dispatch、同步、partial存储和归约成本。先单层对，再跨2层，再扩范围。

### TM3｜Target 主干容量化：补洞，不推倒重来

**来源：附件第二部分缺口四。入口：** `evaluate_target_capacity_admission`、qwen4exp建图、predefined frame/coverage、GDN、多行producer。

**第一阶段范围保持：** TARGET、单序列、同一会话verify_tokens容量，先1..4验证行；prefill、多序列、PLE、QSA、unsupported cached/RBB/chunk变体不顺便放宽。实际模型层数从GGUF/模型元数据取，不让48层和其他RERoT模型的层数混用。

**实现次序：** ① 按“输入/位置→Attention/KV→GDN/conv/indexer→MoE→terminal→collective/下一消费者”生成实际覆盖表；② 对已存在区域只补实际dispatch与状态证据，不重写一遍；③ 修漏掉的active参与、capacity stride和间接参数；④ 测1→4→1→2→3，拒绝后重放、accept=0／部分／全部、state catchup；⑤ 全链证据达标后，用明确的已支持配置条件放行GDN，未知组合保留精确路径。

**必测：** inactive尾部NaN／大值／随机毒数据；active输出与最终KV/recurrent/conv状态；rollback位置；隐藏状态generation；实际fusion/direct producer；跨rank连续epoch与第二个请求。仅“活跃行结果没变”不等于证明没有读inactive行，还需核对实际dispatch访问范围。

**硬交付：** 同一容量下graph UID稳定，稳态CB重录与buffer增长为0；真实有效行计数吻合；全链状态与精确图对拍。admission是最后的发布动作，不是第一笔性能patch。

### TM5｜TP5／MTP 新冻结基线

**来源：附件第二部分缺口五。入口：** `common_speculative_cycle_record`、MTP运行与指标、模型请求harness。

**实现次序：** ① 对当前修复后的Q8Packed、ACT_Q8和shuffle路径重新建立基线；② 固定TP模型与5卡映射；③ 分开Reference、同算术P1A对照、LateBind、MTP各组；④ cycle计时包含draft、target verify、catchup、handoff及摊销费用；⑤ 以实际提交token求单位成本，同时记录客户端墙钟与输出质量。

**必测：** 连续请求复用、draft接受／拒绝、容量变化、EOS、取消、cold/warm与安全退出。旧52.47 tok/s仅为历史参考，不能无条件用于当前胜负判定。不能只以draft接受率高宣布MTP净加速。

### Tnorm｜resume_norm 有限几何搜索

**首轮限定候选：** 现有完全展开、动态循环、分块展开4／8。最多先比较这4种，统一编译器、优化等级、输入、subgroup配置。记录实际code size、VGPR、spill、LDS和GPU时间；不根据code size单独晋级。

## 8. 十问研究线八项：等义工程与近似研究分开

### Q1｜图级公共输入复用 + MoE Expert 聚集

**来源：附件第三部分缺口八。入口：** `llama-graph`、模型 Q/K/V／门控建图和 MoE packing。

**Q1-A（近期）：** 先针对同一hidden-state分叉的norm／activation quantization做具名复用，不先写通用CSE优化器。复用身份包括输入版本、dtype、epsilon、scale／旋转／量化模式及相关参数；共享一个生产者、多个只读消费者。不得把状态写入、RNG、alias后被修改的tensor、不同LoRA／参数的计算当公共表达式。

**Q1-B（独立）：** 按各行真实选中的expert分桶，形成expert→row列表，共用权重tile；恢复原行位置和原路由权重。保持独立激活、相同top-k集合及输出归并契约，不改变模型路由。

**必测：** 相同输入不同参数不被合并；相同参数不同输入版本不被合并；多consumer寿命；LoRA开关；重复expert、零行expert、capacity尾部、不同pen排序。观察算子／量化次数、分配生命周期和batch延迟。跨消费者共享可能延长激活寿命，峰值scratch也计入，不能只看删除的node数。

### Q3｜公共 KV 块多 Reader Attention：近期核心 GPU 方向

**来源：附件第三部分缺口九。入口：** `flash_attn_rerot.comp`、RERoT dispatch，`test-rerot-shared-block.cpp` oracle。

**实现次序：** ① 先做2个Reader一个workgroup／cohort，再比较4；② 公共KV tile一次载入，为每个合法Reader消费各自已预处理的effective Q，并计算独立的局部在线softmax状态；③ 私有／不完全共享段继续走独立路径；④ 用同一query的 `(m,z,u)` 精确组合公共与私有块；⑤ 集成R13后才探索span原生遍历。12个Reader不等于强塞12个完整累积向量到一个workgroup。

**合并式：** `m=max(m1,m2)`；`z=exp(m1-m)z1+exp(m2-m)z2`；`u=exp(m1-m)u1+exp(m2-m)u2`；最后`o=u/z`。两个空块／全mask边界单独按既有语义处理，避免 `-inf - -inf` 生成NaN。不能先把每块输出各自归一化再直接相加。

**必测：** Reader可见集部分相交／互不相交；STRONG/LAG1；private/pending与future-frontier；不同effective_pos；GQA非均匀映射；极端logit；sink／softcap等真实算子参数；空块；一块只对一个Reader可见。比较实际GPU输出，不只跑CPU参考。

**收益账：** KV读取、LDS/VGPR/spill、occupancy相关统计和完整attention时间。CPU的1.36–1.97×不能承诺GPU同倍数。Hydragen证明共享prefix的精确注意力可以复用数据供给，但不能直接证明本仓库任意可见性／DDVR／RDNA2组合的收益【P1】。

### Q5｜GDN 共同基底 + 低秩增量

**来源：附件第三部分缺口十。入口：** `llama-rerot-math.*` 与 GDN state backend；专用GPU递推为新增候选。

**实现次序：** ① 先核验目标更新满足附件的标量门控前提；不满足的模型／模式走稠密；② 状态维护 `S_i=a_i*B+U_i*V_i^T`，每步按真实递推增加必要秩；③ 多Lane共享同一B的投影供给，分支增量各自持有；④ 提前预留稠密物化空间；⑤ 在测得的成本交叉点或数值条件触发完整物化，后续走稠密。

**不可做：** 截断“小增量”却仍标等义；忘记固定入口已消耗的秩；靠伪共享基底抹平分支差异；在同一次候选里改变门控数学。

**必测：** r=0、1、交叉点±1、长弱衰减、极小a、转稠密边界、换笔/恢复/rollback；对原稠密递推同时检查状态相对误差与下游输出绝对误差，避免小范数／大状态量级掩盖问题。d=128粗略公式值为32；真实阈值由GPU测量，不硬编码53。

### Q6｜已知 Token 的 WY 块折叠

**来源：附件第三部分缺口十一。入口：** GDN多步路径、fixed-entry replay、TARGET验证块、`llama-rerot-math` oracle。

**实现次序：** ① 复用当前参考层的damping、beta行索引和三角求解约定；② 从T=2开始，扩4／8；③ 比较逐token状态写回与块内递推，最终状态只在必要边界物化；④ 固定入口和已知draft token块优先接入，未知未来token不适用。

**必测：** beta=0／1、变长active、数值极端、head映射、最后不足块、每个中间所需输出和最终状态；FP64逐步oracle、FP32旧实现、GPU三方比较。附件2.5e-5是旧测试样本的结果，不是所有模型固定容差；按dtype、长度和幅值建立误差预算，失败不直接放宽。

**因果边界：** GDN块化不等于Attention能看见未发布的Peer token；同块跨笔仍按frontier与发布边界隔离。与TM3共用active/capacity契约，但不要求先把所有模型的TARGET放开才能做独立算子。

### Q7｜PQ2_0 位平面/LUT：矩阵级实验，不重走单dot亏损路线

**来源：附件第三部分缺口十二。入口：** PQ2_0投影、R07小批矩阵、`block_pq2_0`真实格式。

**实现次序：** ① 保留实际4码值{-1,0,+1,+2}和scale；② 每个activation小组建16项表，并让足够多输出weight行复用；③ 比较寄存器／LDS表、查表布局与已有decode+dot；④ b=1/2/4/6、不同输出M和K长度分别画交叉点。首轮只做少量明确几何候选，不无限搜索。

**必测：** 每一种bit-plane组合、128块边界、scale尾数、不同block／tensor offset、非满tile、多行激活不能相互覆盖表。真实GPU输出和现有CPU位级解码oracle对拍。

**收益账：** 包含建表、索引、LDS／寄存器压力和权重读取，不能只比较乘法次数。T-MAC是CPU路线的实证，不是RX6800上LUT胜出的证明【P2】。已有单vec_dot负结论只否定那个粒度，不等于矩阵级研究无价值。

### Q8｜上下文跳块：近似路线，先shadow再放行

**来源：附件第三部分缺口十三。入口：** KV块元数据、score界预检、attention任务表。

**实现次序：** ① 维护有版本的key中心／半径与value范数上界；② 先只预测可跳块并照常计算，实测界的保守性和元数据成本；③ 再在独立开关下跳块；④ 对失效／不支持的score变换块直接计算，不使用旧上界冒充有效。

**必测：** stale摘要、append/publish/reclaim、极端query norm、误差预算累积、多块同时跳过、quantization舍入与softcap等实际score操作。附件 `||o-o_keep|| <= 2 Vmax δ` 的δ是被省略概率质量，不是块比例；估计δ必须说明分母／上界来源。

**质量与发布：** 单attention误差界不能推出最终token、长文质量或任务正确性界。独立评测long-context检索、困难任务、生成质量与MTP接受率；没有收益或质量预算不满足就保留关闭，绝不把近似跳块收益计入等义优化包。

### Q9｜LM Head 与 GPU 采样：先贪心，再保持生产链语义

**来源：附件第三部分缺口十四。入口：** LM head输出、采样器、`tools/server/server-context.cpp` grammar/penalty/pending decision。

**实现次序：** ① 无grammar的greedy路径先做分块argmax，只回传token ID和必要分数；② 扩展明确支持的top-k；③ top-p保证全局概率质量与生产配置的链序；④ 与grammar、penalty、EOS和状态事件联调。不支持的配置在采样前明确走CPU，不静默少做处理。

**RNG策略：** 首个等义版本可保留CPU现有RNG，只上传相同uniform draw以隔离随机数算法差异；之后再证明per-pen GPU流等价。必须保持每pen计数、分支接受／拒绝、pending decision、换笔和回滚一致。

**必测：** logits ties、top-k边界、top-p临界、temperature=0／非1、grammar拒绝、罚项、行置换、cohort大小变化；在匹配随机draw下对拍token选择。`tests/test-rerot-math.cpp:1399–1455` 的生产对照链实际是 top_k→top_p→temp→dist，附近旧注释有不同说法，不能按注释重排生产链。当前kept-set一致不等于RNG轨迹一致。

**收益账：** 回传字节、LMhead后处理、请求延迟与CPU占用；不能用低成本但改变top-p集合的近似采样伪装等义实现。

### Q10｜K×H 联合投机：先最小网格和完整回滚

**来源：附件第三部分缺口十五。入口：** `verify_grid`、frontier调度、KV/GDN/sampler事务。

**实现次序：** ① 先固定K=2、H=2、普通BODY，不包括动态增删cohort／换笔／synthesis；② 用可控草稿或oracle回放fixture验证，不以“尚未训练联合模型”阻止状态机实现；③ 每列按STRONG边界验证，拒绝传播到真实依赖下游；④ 统一回滚KV、recurrent、采样RNG、grammar/penalty和pending decision；⑤ 扩到真实草稿器，另记训练或设计任务。

**必测：** 第0／中／末列拒绝，菱形依赖、下游曾读被拒token、同列部分成功、事件重放、随机种子重放。先做greedy网格等义验证；要做随机精确投机，需使用联合条件分布及相应接受／残差采样机制，不能把每笔独立接受率直接相乘当正确性证明。

**交付：** 最小可运行GPU状态回滚原型、与naive反例的对照、完整成本账。没有净收益可以缩短H或关闭候选；这个任务不阻塞普通MTP、Q3、Q6等已知路径。

### H17｜写入端长 Span 亲和性

## 10. 验证体系：每步有证据，但不每步重跑全部世界

### 10.1 四层测试与晋级

| 层 | 必须取得的证据 | 可以并行的事 |
|---|---|---|
| L0：静态／CPU | 编译、ABI大小与范围、独立oracle、CPU-only状态事务、mock失败路径 | 全部未启用GPU候选继续编码 |

| L3：性能／默认启用 | 同SHA或版本配对、同数值与工作负载、收益区间、资源和质量合格 | 不胜出保留关闭或形状选择，不强行上线 |

## 11. 可信收益测量：两个模型轨道，三种分母

### 11.1 冻结两条互不混淆的轨道

**轨道R：** RERoT适用模型、真实DAG与Reader/上下文形状；关注完整任务完成时间和多笔有用产出。  
**轨道T：** TP5对应模型、五卡布局、同步和wire、MTP容量与LateBind模式；关注实际提交token与cycle成本。

模型名、量化格式、层数和文件hash从当前加载对象确认。R轨道的单卡模型／多Pen结论，不能作为T轨道五卡48层主干的状态证明；T轨道历史52.47 tok/s也不能当R轨道的新基线。

### 11.2 三种指标同时报告，但不可混算

**任务指标：** 相同DAG／相同语义任务的客户端完整墙钟、TTFT、p50/p95、最终可见token。串行对照应执行相同任务图，不仅把RERoT关掉后让单prompt自由生成另一套工作。

**计算指标：** 全部model-forward token和各phase内部token，反映硬件利用与额外工作量；这是诊断指标，不保证用户任务更早完成。

**MTP指标：** 完整cycle耗时／实际提交token，拒绝draft、catchup、handoff、无提交cycle都计费。另列接受率和候选长度，不能用接受率替代净收益。

可用的恒等关系检查：每请求计账守恒、每cycle token接受/拒绝/提交匹配、phase覆盖。存在CPU/GPU重叠时，阶段duration可重叠，不能把其和强行当wall time；收益按关键路径和请求墙钟归因。

### 11.3 基线与候选的采样纪律

正式A/B固定：模型hash、编译器/flags、驱动/运行环境、设备/rank映射、线程/NUMA、prompt与DAG、数值模式、同步/wire、cache冷热状态、seed或固定轨迹、输出预算、context容量、所覆盖路由。

先取得同版本A/A噪声。先在profile开启下定位，再关闭非必要profile做吞吐；不能A开详细trace、B关trace。冷启动单列，包括图定义／首转换；温态前缀命中／状态恢复按同一规则。状态重置和模型重载不隐瞒；冷任务计完整成本，温任务明确其前提。

可采用AB/BA交替，2个pair构成ABBA。**默认建议的正式首轮预算是6个ABBA块，即A与B各12次，而不是12次总请求**；这是候选通过短语义测试后的建议测量预算，必须在已批准请求包络内。按pair计算速度比／耗时差，按块评估区间，避免把相关请求当独立样本。样本太少只报探索结果，不给p95稳定性或长期可靠性背书。

资源不支持同驻两个大模型时，两个构建/配置顺序运行；每个版本单独warmup并附完整退出证据。绝不为方便A/B同时挤入两份模型造成超预算，也不要在不安全状态反复stop/start。

### 11.4 候选胜出规则（建议默认值，非已知事实）

首先所有语义、状态与route检查通过。然后同口径中位性能提升建议至少2%，且配对速度比区间下界高于1。代表性非目标形状不宜回退超过2%，p95任务时延不宜恶化超过5%；阈值在测前按用户目标冻结，不能测后改。

若结果处于噪声区，可在包络内扩一次采样；仍无结论则记INCONCLUSIVE，保留关闭／按有证据形状选择，继续下一候选。负收益记REJECTED，不反复改描述或挑最小值。微基准胜出、端到端没胜出，记录微优化但不计本期主收益。

总收益用组合版本实测，不把多个patch各自的提升百分比相加。全特性测量至少包括target-only、+MTP、+各主要候选、组合包和有明显交互的消融。TriAttention、FlashPrefill、XKV等组合是否适用由实际route记录，不适用标N/A。
