rev10: contract driver now follows the production loader order

File changed (only this one): examples/tp5-router-verify/router-fixture-contract.cpp

Why: rev9 reached load_hparams, then called load_tensors without load_vocab. The production
path (src/llama.cpp:337-356) is
    load_hparams -> (CLIP guard) -> load_vocab -> load_stats -> print_info -> load_tensors
and load_vocab is the pass that reads qwen4exp.vocab_size. Without it the model kept
n_vocab == 0, so load_arch_tensors asked for token_embd [8, 0] -- the rev9 contract failure
(lead-router-rope-verify-20261031/VERIFY-ROUTER-REV9-CONTRACT.txt). The fixture's GGUF already
carries qwen4exp.vocab_size = 128; nothing in the file needed to change.

What the checker does now:
1. model = llama_model_create(LLM_ARCH_QWEN4EXP, mparams)  [unchanged from rev9]
2. load_hparams(ml)                      -> problems labelled "hparams:"
3. load_vocab(ml); load_stats(ml)        -> problems labelled "vocab:"; additionally fails if
                                            llama_vocab_n_tokens(llama_model_get_vocab(&model))
                                            is still 0 (an empty vocab is a failure, not a detail)
4. load_tensors(ml)                      -> only when (2) and (3) succeeded; problems labelled
                                            "tensors:"
5. binding/shape checks over the model's own tensors
6. per-tensor F32 / non-empty checks on the file (independent of the loader passes)

Release paths: every early return frees the gguf context and, once created, the model
(delete model_raw; llama_model has a virtual destructor; no tensor data was materialized under
no_alloc). The normal path runs that teardown once, model first and the gguf context last,
because llama_model_loader holds a non-owning pointer to it. No double free, no leak, and no
path reports success after a failed pass.

Nothing else changed: no production source, no patch, no change to the fixture's metadata or
tensors, no change to the verifier or to run-router-cpu.sh's criteria. Docs updated:
ROUTER_SCRATCH_CPU_FIXTURE.md §6/§7 and HANDOFF-ROUTER-CPU-FIXTURE-REV9.txt.
