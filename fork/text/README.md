# Incremental generation text

`TQText` turns chunks of generated bytes into valid UTF-8 output and detects configured stop strings. One `generation_stream` owns one output stream. It does not tokenize, sample, call a model, write JSON, perform I/O, or depend on another extension library.

The caller supplies bytes and receives owned result values. Chunk boundaries do not change the final text or selected stop. The caller must serialize operations on one instance; separate instances are independent.

## Build and use

Only C++17, its standard library, and CMake 3.16 or newer are required.

```sh
cmake -S fork/text -B build-text -DCMAKE_INSTALL_PREFIX=/absolute/path/to/install
cmake --build build-text -j 4
ctest --test-dir build-text --output-on-failure
cmake --install build-text
```

An independent consumer uses the installed package:

```cmake
find_package(TQText CONFIG REQUIRED)
target_link_libraries(my_program PRIVATE TQText::text)
```

```cpp
#include <tq/text/stream.h>

tq::text::generation_stream text({"<end>"});
auto first = text.push("Hello <en");
// first.text == "Hello ", first.offset == 0, first.finished == false
auto last = text.push("d>ignored");
// last.text is empty, last.offset == 6, last.finished == true
// last.stop_index == 0
```

`BUILD_TESTING=OFF` disables this package's standalone tests. The default is `ON`.

## Messages and ownership

`push(std::string_view)` reads its argument only during the call. `finish()` declares that no more input bytes will arrive. Both return `stream_delta`:

| Field | Meaning |
|---|---|
| `offset` | Number of output UTF-8 bytes emitted before this result |
| `text` | Owned, valid UTF-8 text that is now safe to emit |
| `finished` | The stream ended, either at a stop or through `finish()` |
| `stop_index` | Original configuration index of the matched stop, or no value |

Empty deltas are valid. A token piece may contain only an incomplete UTF-8 sequence or a possible stop prefix. The caller must not emit the original piece while its bytes are held by the stream.

Offsets count displayed output bytes. They do not count input bytes, token IDs, Unicode characters, or model positions. A consumer can verify that each delta starts exactly where the previous one ended. Editing a returned string does not change later offsets or results.

The constructor validates and copies the stop strings. Later changes to the caller's vector do not change a stream. Streams cannot be copied. Moving one transfers its configuration, pending text, byte cursor, and terminal state; the moved-from object is finished with an empty result and a zero offset. There is no implicit reset or shared mutable state.

## UTF-8 policy

Valid UTF-8 is preserved byte for byte, including NUL and control characters. An incomplete sequence stays pending while it can still become valid. At most three raw bytes need to wait for a continuation.

Each invalid byte becomes one U+FFFD replacement character. This is a per-byte rule, not a rule that merges a run of invalid bytes into one replacement. For example, a final `E2 82` prefix becomes two replacements when `finish()` is called. An invalid following byte first rejects the pending prefix, then receives its own normal processing. Overlong encodings, surrogate scalars, and values above U+10FFFF are invalid.

This policy preserves the previous batch program's final JSON text interpretation while making each emitted delta valid UTF-8. It does not normalize Unicode, escape JSON or HTML, apply a grapheme rule, or filter control characters. Those formats remain the caller's responsibility.

## Stop selection

Stops must be nonempty, valid UTF-8 strings. The limits are 32 strings, 4096 bytes per string, and 65536 total bytes. Bounds are checked before the library copies the strings or builds match tables. Duplicates are allowed and retain their original indices.

Matching uses the rendered UTF-8 bytes, including any replacement characters. It is exact and case-sensitive; there is no Unicode normalization. The selection rule is:

1. Stop at the first byte position where any configured string completes.
2. If several strings complete there, choose the longest one.
3. Equal strings at that position use the earliest configuration index.

For stops `abc` and `b`, input `abc` stops at `b` and emits `a`: `b` completes before `abc`. For stops `bc` and `abc`, input `zabc` selects `abc`, because both complete at the same position and `abc` is longer. This rule is the same whether the input arrives in one message or in many pieces.

Matched stop bytes and all later bytes are suppressed. Text that might still become a stop remains pending. `finish()` emits that pending text if no stop completes. UTF-8 replacements generated by `finish()` can themselves complete a stop, so callers must inspect `stop_index` on its result too.

After a stop or a successful `finish()`, `push()` throws `std::logic_error`, including for an empty input. Repeated `finish()` returns an empty terminal delta at the current byte offset and preserves the selected stop index. It cannot emit text twice.

## Resource and failure contract

The object keeps copied stop strings, prefix match tables, one match position per stop, and a fixed ring with capacity equal to the longest stop. It keeps no emitted text history. Between calls, the pending stop suffix is shorter than the longest stop, with at most three additional raw UTF-8 bytes pending. Prefix tables use space proportional to the bounded total stop bytes.

A result string uses memory proportional to the current input message and pending bytes. There is no fixed input-message limit beyond representable string and output-counter capacity. Worst-case output capacity is checked and reserved before the stream changes state: each invalid input byte can expand to three UTF-8 bytes. A reported allocation or capacity error leaves the stream unchanged. Invalid stop configuration throws `std::invalid_argument`; a result or byte-counter overflow throws `std::length_error`.

Matching uses prefix tables and a ring, so repeated long stop prefixes do not shift or rescan emitted history. No measured inference-speed or memory-performance benefit is claimed.

## Composition with a model

The batch program owns model calls, samplers, token IDs, request identities, output I/O, and sequence release. It sends the bytes returned by the public detokenizer to this library, appends returned text, and uses a terminal stop to prevent further decoding for that request. It must keep the sampled token that contained the stop in token accounting, even if part of its displayed text is suppressed.

On an EOG or length boundary the caller calls `finish()` and consumes that result before it emits the final response. A text delta or its offset is not proof that a network peer received it. HTTP retries, delivery acknowledgments, usage aggregation, and persistent resume are outside this library.

## Verification

`tests/stream-test.cpp` compares the incremental object with a separate complete-input reference that repairs UTF-8 and scans for the first completed stop. It checks every partition of short fixtures, generated byte sequences, all 256 byte values, long repeated prefixes, a wrapped stop, overlapping and duplicate stops, NUL, split scalar values, invalid UTF-8, and a stop created only by end-of-input replacement.

Each result must be valid UTF-8, have the correct byte offset, and remain a prefix of the final reference output. Additional checks cover configuration limits, caller input/result changes, independent interleaved streams, move ownership, repeated finish, and input after termination. These are standalone B tests; actual model and output-stream qualification belongs to the C consumer.
